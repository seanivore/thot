## Bucket Purpose

Define who Thot is for. The working thesis (per `docs/archive/v4_0/UPDATE_v4_0_0.md` and Sean's session notes): **Thot is a Word-processor replacement that uses markdown semantics — not a markdown editor pitched at devs.** The "little bits of magic" markdown users get from IDE-style highlighting (instantly seeing structure without searching for it — reduced cognitive load) should be accessible to people who'd never voluntarily learn markdown.

This bucket's research either confirms that thesis or surfaces a sharper one.

---

## Initial Research Questions

1. **Who is the wider audience?** Marketing teams, writers, students, knowledge workers using Google Docs / Notion / Word today. What are their actual workflows and pain points?
2. **What cognitive-load wins translate without markdown literacy?** Color-coded structure, hanging indents, instant heading navigation, todo checkboxes — which of these would a Notion/Word user notice and value? Which require explanation?
3. **Adjacent landscape** — survey: Notion, Craft, Bear, Obsidian, Drafts, iA Writer, Ulysses, Typora, HackMD. Which already serve non-dev audiences? Where are the gaps?
4. **What's the wedge?** What does Thot do that no one else does, that the wider audience would care about? (Candidate from Sean's notes: real-time collab for markdown teams — but that overlaps with the `collab-for-markdown` bucket.)
5. **Naming/positioning copy** — does "Thot" land for the wider audience, or is it dev-coded? Is the deployed URL `thots.august.style` strong or limiting?
6. **Distribution surface** — web/PWA reaches anyone with a browser. App stores reach iOS/macOS users. Browser extensions reach a different sliver. Which surfaces matter for the audience?

---

## Priors / Known Constraints

- Sean's existing PWA users are likely dev-adjacent. Don't optimize for that audience exclusively.
- The IDE-style highlighting (color tokens, hanging indents, semantic structure) is already built and working in v3.1.2. The product question is whether the audience values it; the technical groundwork exists.
- Sean explicitly does *not* want Thot to be "another markdown editor" in branding or positioning.
